# AI usage disclosure

## Which AI tools were used?

- **Claude Code** (Anthropic), running in a cloud session with access to this repository.

## How were they used?

I used Claude Code as a pair programmer that did most of the typing, while I made the
product and scoping decisions:

1. **Choosing the challenge.** I gave Claude both briefs and talked through the trade-offs.
   I chose the Spaceship X26 PRMS because its open-ended rules (tier inheritance, the
   Crew Lead invariant, auditing, reporting) leave more room for real design decisions.
2. **Scoping.** I picked TypeScript and asked for a full web application rather than a CLI:
   passengers _book_ resources, and Crew Leads get an admin module. Claude proposed the
   layered architecture (domain / api / web) and the booking model (time slot + capacity +
   check-in), and I approved it before any code was written.
3. **Implementation.** Claude built the system level by level, test-first: tests for each
   domain module, then the implementation, then a commit. The API and web layers followed
   the same order. The commit history shows that progression.
4. **Verification.** Claude ran the full suite (lint, typecheck, 164 tests), deliberately
   broke the booking lock to prove the concurrency test can fail, did a production build
   from a clean clone, and walked through the real UI in a headless browser (desktop and
   mobile) to catch integration problems.
5. **Documentation.** The README, design notes and assumptions log were drafted by Claude
   from the decisions made along the way.

## Which portions were AI-assisted?

Effectively **all of the code, tests and documentation were generated by Claude Code** under
my direction. The decisions that were mine:

- which challenge to take, the language, and the "full web app with booking" product direction
- approving the architecture and the booking model
- the repository, its history and the submission

## Prompts / workflow worth sharing

The main prompts were short and conversational:

> "Attached are 2 coding challenges… Which one do you prefer? Personally I like the space
> resource management better."

> "Why don't we create a full fledged web app. I can imagine that as normal passengers, they
> get to book the resources. For lead / admin, they have access to an admin module to handle
> administrative stuff."

> "go"

Most of the leverage came from agreeing on the shape up front (layers, booking model, test
strategy, commit per level) and then letting the agent run with tight feedback loops: write
a test, watch it fail, implement, run lint, typecheck and tests, commit, push. Writing
`docs/ASSUMPTIONS.md` turned the brief's ambiguity into explicit, reviewable decisions
instead of hidden ones.
